# Instance/Protocol Database Update

Use a small Markdown knowledge base:

```text
<database>/
  sources.md
  queue.md
  instances/*.md
  protocols/*.md
  turns/<work-item-id>.context.md
  turns/<work-item-id>.md
```

The repository's default live database is `lab_records/instance_protocol_db/`. Treat it as durable local state, update it serially, and do
not add it to Git. Timestamped test runs may freeze before/after copies, but they are not alternate live databases.

Canonical coherent spans remain external evidence. Do not create span records or copy canonical span data into the database. Mention a span
where it matters—in an instance membership, the queue, or a turn note. Use `rg <span-id> instances queue.md` to find its current treatment.
The generated `.context.md` is a compact retrieval bootstrap; the shorter same-ID turn note is the durable account of the update. The
context intentionally omits full episode membership rows, the complete notebook-summary collection, and the complete database catalog. Open
canonical tables, compressed notebooks, and database records progressively as the work requires.

Treat queue history as the span-resolution ledger. A span referenced by an instance is assigned but is resolved only after appearing in a
resolved queue row. Never-resolved spans may be queued once. Previously resolved spans may gain memberships during later turns but must not
be queued again.

## Records

An **instance** is one execution of an experimental plan with a shared objective and coordinated arms. It can cross spans, media, conditions,
and dates. Distinguish the experiment that generated or maintained cells from later experiments that sampled, characterized, or assayed
them. A selected LTEE passage may belong to the whole longitudinal LTEE and, as a sampled subset, to a later flow-cytometry experiment.

A **protocol** is a discrete reusable method with a purpose, an ordered procedure, and named resources. Assign every new protocol to exactly
one method family:

- `culture`: grow, maintain, passage, condition, freeze, thaw, or otherwise handle cells without making the manipulation itself the measured
  endpoint;
- `modification`: deliberately alter cells, for example by transfection, transduction, selection, gene editing, or treatment intended to
  establish a changed state;
- `measurement`: observe or assay cells or material derived from them, for example by microscopy, flow cytometry, viability measurement,
  sequencing preparation, karyotyping, or metabolomics collection.

Keep protocols general across cell lines, media, and experimental instances when the reusable method is the same. In each instance's
`Protocols` section, document how the protocol was applied, execution-specific parameters, and explicit exceptions or deviations. Routine
changes in cell line, medium, dose, timing, setpoint, plate format, or instrument belong there unless they change the reusable method itself.
A medium, setpoint, condition, aim, or result alone is not a protocol. If one instance uses methods from several families, link several
discrete protocols rather than forcing the full execution into one protocol.

Use the templates as writing prompts, not schemas. Write what the evidence supports and leave uncertainties visible. Relate upstream and
downstream instances in ordinary Markdown, using clear phrases such as “provides samples to” or “samples generated by.”

## One turn

Process one pending row from `queue.md`:

1. Run `prepare-instance-update-turn.py` and read the generated compact context. It surfaces one summary row per input span, aggregated
   notebook leads, direct instance overlap, source paths, and progressive retrieval examples.
2. Discover the relevant evidence progressively. For passage and episode identifiers, start with a full fixed-string match (`rg -F`). If it
   is absent, remove only a suffix whose meaning is understood, then try a still-informative composite substring. Use an `rg` regular
   expression only to broaden a deliberate component, such as an `A[0-9]+` passage. In regex mode `|` means OR; do not combine generic
   fragments merely to increase hits. Avoid isolated passage labels and cell-line-only searches unless narrower searches fail for a reason.
   Read the selected notebook summaries and compressed paragraphs. Matching results and summaries are retrieval hints; factual claims must
   cite compressed notebooks or canonical span data.
3. Ask both questions explicitly:
   - What experiment generated or maintained these cells?
   - What later experiments sampled, characterized, or assayed them?
4. Create or improve every supported instance and protocol. Reuse a general protocol when its purpose, core procedure, and assay/readout are
   materially the same; put execution-specific parameters and exceptions in the instance. Find the complete universe of other participating
   spans and add supported memberships immediately. Classify candidates against all queue history: put only never-resolved candidates in one
   follow-up row; do not duplicate candidates already pending; update previously resolved spans in place without requeueing them. Do not
   truncate or batch the candidate universe.
5. Mark the current queue row resolved and write one concise turn note describing sources read, changes made, important judgments, and
   candidate handling. Do not requeue the current input.

Evidence favoring one instance includes a shared aim or experiment name, direct lineage continuity, synchronized arms or controls, planned
condition changes, or longitudinal tracking for one objective. Evidence favoring separate instances includes a new execution, aim,
intervention, assay, or derivative characterized independently. Dates, medium, or cell line alone are insufficient.

Treat derivative suffixes such as `K` and `KD` separately from their unsuffixed parent lineage unless notebook evidence supports a shared
membership. Treat canonical tables as evidence for lineage, dates, conditions, and membership—not as sources for laboratory observations or
protocol steps.

## Tools

- `prepare-instance-update-turn.py`: choose one pending row and create a compact Markdown retrieval bootstrap.
- `catalog-instance-protocol-db.py`: summarize existing Markdown records.
- `search-coherent-spans.py`: return the complete related-span candidate set; pass `--database` to annotate candidates as unseen, pending, or
  resolved. Rankings remain hints.
- `surface-notebook-summaries.py`: show short or selected medium summaries when targeted retrieval requires them.
- `search-lab-records.py` and `extract-notebook-evidence.py`: retrieve compressed-notebook evidence.
- `validate-instance-protocol-db.py`: perform only structural checks—paths, IDs, references, queue spans, and turn notes.
- `run-instance-update-test.py`: run up to `--max-turns`, stopping on failure or completion. An initially empty queue seeds the longest
  never-resolved span. With `--stop-when-queue-empty`, the runner stops when the queue next becomes empty after one or more turns; without it,
  each empty queue seeds the next longest never-resolved span. Every turn gets frozen before/after states, validation, and `events.txt`.

Do not consult legacy protocol or instance catalogs unless explicitly requested.
